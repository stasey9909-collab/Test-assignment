# ASSETS.md — материалы для проекта «Общество»

Файл описывает все графические материалы проекта: откуда взят
исходник (`media/…`, оригиналы пользователя — не изменяются и не
удаляются), в какую рабочую копию он превращён (`public/assets/…`,
латиница, оптимизированный формат) и как используется — как контент
сайта или только как визуальный референс для дизайна.

Компонент [`PlaceholderImage`](src/components/ui/PlaceholderImage.tsx)
устроен так, что подстановка реального файла не требует правки кода:
если по указанному пути появляется изображение — оно просто заменяет
градиентную заглушку (заглушка показывается только тогда, когда
`<img>` не смог загрузиться).

## 3. Декоративные предметы — `public/assets/flying-pieces/` (контент, для scroll-сцены)

Источник по-прежнему один студийный композит с реальной альфа-прозрачностью
(`public/assets/decor/game-pieces-set.png`, 1536×1024, оригинал —
`media/ChatGPT Image 31 июл. 2026 г., 20_47_21 (1).png`), но теперь из него
вырезаны 9 **отдельных** PNG/WebP-файлов — по одному на кубик/фишку, а не
один общий файл с CSS `background-position`-кропом. Ассеты сгенерированы
временным `sharp` (`npm install --no-save sharp`, использован и сразу
удалён) в два прохода:

1. Первый проход — точный пиксельный `extract()` по уже имевшимся
   координатам bounding box (тот же альфа-анализ, что и раньше, координаты
   в `src/data/flyingGamePieces.ts`). На плотно упакованном композите это
   оставляло по краям кропа мелкие обрывки соседних предметов.
2. Второй проход (после обратной связи о «мусоре» вокруг фишек/кубиков) —
   на каждый кроп поверх `extract()` наложен связный-компонентный
   flood-fill (BFS от центра кропа, 4-связность, порог по альфе), который
   обнуляет альфу у всего, что не связано с главным объектом, а затем
   `.trim()` обрезает канвас по уже однозначному силуэту. Отдельно:
   `sharp().trim()` сразу после `.extract()` на части кропов падал с
   `bad extract area` — оказалось, что дело не в геометрии прямоугольника,
   а в том, что `trim` не мог однозначно определить границу на сыром
   кропе с обрывками соседних объектов; после flood-fill-очистки `trim`
   отрабатывает без ошибок на всех 9 кропах.

| Рабочий путь | Что на кадре |
| --- | --- |
| `public/assets/flying-pieces/chip-red-5.webp` | Фишка «5», красная |
| `public/assets/flying-pieces/chip-blue-50.webp` | Фишка «50», синяя |
| `public/assets/flying-pieces/chip-black-100.webp` | Фишка «100», чёрная |
| `public/assets/flying-pieces/chip-white-1.webp` | Фишка «1», бело-синяя |
| `public/assets/flying-pieces/chip-green-25.webp` | Фишка «25», зелёная |
| `public/assets/flying-pieces/die-top.webp`, `die-left.webp`, `die-right.webp`, `die-bottom.webp` | 4 кубика |

Переработка блока опиралась на приложенное видео-референс
(`media/Разлетающиеся предметы.mp4`, 2 сек, 1536×1024) — разобрано
покадрово через `<video>.currentTime` в браузере (ffmpeg в окружении нет):
предметы стартуют собранными в центре и почти сразу (первые ~0.4 с из 2)
расходятся в финальную сетку 3×3, две угловые фишки («1» и «25») оседают
довёрнутыми по Y (эффект «ребром»), кубики слегка кувыркаются, центральная
красная «5» остаётся ближе к центру композиции. Позиции/повороты в
`flyingGamePieces.ts` авторские, но пропорции и характер разлёта сверены
с этим видео.

`src/lib/spriteCrop.ts` (утилита для CSS-кропа из общего спрайта) удалена
как более не используемая — единственным потребителем был старый
`flyingGamePieces.ts`.

Старые `dice.webp`/`poker-chips.webp` (фото с непрозрачным белым фоном,
вырезанные под них мелкие/размытые крупы читались как нечёткие цветные
пятна, а не узнаваемые кубики/фишки) — удалены ещё раньше, вместе со
старым компонентом `GamePiecesScrollScene`.

## 5d. Футер — `public/assets/footer/` (контент, готово к использованию)

Крупный объёмный предмет в футере (между блоком ссылок и большим
логотипом) — стопки покерных фишек вместо кубиков (по запросу).
Исходник — `media/фишки.jpg` (1310×1200, JPEG, сплошной белый фон, без
альфа-канала).

Белый фон убран вручную через временный `sharp`, т.к. готового
инструмента удаления фона в окружении нет: flood-fill от границ кадра
по «почти белым» пикселям (порог `r,g,b > 225`), чтобы не задеть
светлые части самих фишек (например, кремовую фишку «1») — заливка
идёт только от краёв изображения и останавливается на контуре фишек.
Полученную маску слегка размыл (`blur(1.2)`) только по краю через
`extractChannel(0)` перед `joinChannel` — без этого шага sharp
незаметно повышает 1-канальный (grayscale) буфер до 3 каналов при
любой операции вроде `blur()`, из-за чего `joinChannel` неверно читает
байты и результат превращается в горизontальные полосы (нашёл и
исправил это в процессе). Результат — WebP с реальной прозрачностью,
900×823px, качество 90. В вёрстке — без рамки/подложки, с CSS
`drop-shadow`, как и кубики раньше.

| Исходный файл | Рабочий путь | Где используется |
