# «Общество» — лендинг игры «покер на знания»

Авторская визуальная концепция лендинга для интеллектуально-развлекательной
игры «Общество» (тестовое задание веб-дизайнера). Не копирует дизайн
[ogameo.ru](https://ogameo.ru/), сохраняет продуктовую логику и текстовые
смыслы, но соединяет три направления в одну систему: editorial lifestyle
(крупная типографика, воздух, журнальная композиция), premium event-space
(светлый лофт как часть продукта) и лёгкий азарт интеллектуальной игры —
без единого клише казино.

## Стек

- **React 19 + TypeScript**, сборка на **Vite**
- **Tailwind CSS v4** (дизайн-токены заданы через CSS-переменные в
  [`src/index.css`](src/index.css) и подключены в Tailwind через `@theme`)
- **GSAP + ScrollTrigger** — кинематографичная scroll-сцена с игральными
  кубиками и фишками ([`GamePiecesScrollScene`](src/components/scenes/GamePiecesScrollScene.tsx))
- **Framer Motion** — более простые UI-переходы: scroll-reveal, раскрытие
  FAQ, мобильное меню; уважает `prefers-reduced-motion`
- **lucide-react** — иконки

Lenis для смузи-скролла сознательно **не подключён**: нативный скролл уже
работает предсказуемо с якорной навигацией, `scroll-behavior: smooth` и
GSAP ScrollTrigger; синтетический скролл добавил бы риск для клавиатурной
навигации и `prefers-reduced-motion` без реальной пользы для этого макета.

## Запуск проекта

```bash
npm install
npm run dev       # локальный сервер разработки (http://localhost:5173)
npm run build     # проверка типов (tsc -b) + продакшн-сборка в dist/
npm run preview   # локальный просмотр собранной версии
npm run lint      # oxlint
```

Node.js 20+ рекомендуется (проверено на Node 24).

## Дизайн-система

Все токены — в `:root` в [`src/index.css`](src/index.css):

- **Фон**: тёплый молочный `#F1ECE5`, светлая поверхность `#FBF9F5`,
  чистый светлый блок `#FFFDF9`, дополнительный бежевый (альтернирующие
  секции) `#CBB9A7`, серо-бежевый `#A9998A`
- **Текст**: тёмно-коричневый `#28211E`, приглушённый `#746A63`
- **Акценты**: бордовый `#8A1728` — строго для CTA, игровых маркеров,
  активных состояний, цифр и акцентных линий; приглушённый оливковый
  `#65705B` — вторичный акцент; глубокий коричневый `#362724` — для
  немногочисленных тёмных блоков (не более ~15–20% страницы: event-секция
  «Праздник под ключ», цитата о блефе)
- **Шрифты**: Onest (интерфейс, кнопки, формы, подписи) + Cormorant
  Garamond (крупные редакционные заголовки), оба поддерживают кириллицу.
  Serif используется точечно — весь интерфейс на гротеске
- **Флюидная типографика** через `clamp()` (см. `--text-display`,
  `--text-title`, `--text-h2` в `index.css`): hero-масштаб (~56→160px)
  зарезервирован за короткими словами/фразами (слово «Общество» в
  scroll-сцене — приём из референсов, где так набран весь бренд-заголовок
  сайта), заголовок Hero и секций — на тир ниже (~36→100px), поскольку это
  полноценные предложения, а не однословный логотип
- **Контейнер**: максимум 1320px, отступы 64px (desktop) / 48px (tablet)
  / 20px (mobile)
- **Скругления**: варьируются осознанно — `--radius-xs` 16px (поля форм),
  `--radius-sm` 22px (мелкие карточки/теги), `--radius-md` 32px (обычные
  карточки), `--radius-lg` 48px (флагманские поверхности: hero-фото,
  большая карточка условий, тёмные feature-блоки); кнопки-капсулы
  52–58px высотой
- **Редакционные детали**: нумерованные бейджи-медальоны у заголовков
  секций (`SectionTitle` c `index="01"…"06"`); тонкая «рельса» игрового
  стола за карточками-ответами в блоке ключевых слов; курсивные подписи
  под фотографиями в стиле lifestyle-журнала; асимметричная пара фото
  (широкое + узкое внахлёст) вместо одинаковой сетки

Никаких казино-клише (чёрно-красный неон, рулетка, игровые автоматы,
золотые слитки, джекпоты) — вместо этого игровые карточки-подсказки,
фишки, рукописные пометки и мягкие тени.

## Scroll-сцена с кубиками и фишками

[`FlyingGamePieces`](src/components/scenes/FlyingGamePieces.tsx) — второй
блок сайта: 4 кубика + 5 фишек рождаются из центра, невидимые и слегка
уменьшенные, и по мере скролла разлетаются радиально в разные стороны,
частично выходя за пределы собственной секции и заходя на Hero сверху и
на `Keywords` снизу — декоративный слой поверх соседних секций, а не
анимация, запертая в одном контейнере.

Все 9 предметов вырезаны из одной студийной композиции с настоящей
альфа-прозрачностью (см. ASSETS.md §3) через
[`spriteCrop.ts`](src/lib/spriteCrop.ts); координаты вырезки — точные
bounding box каждого предмета, найденные анализом альфа-канала, а не на
глаз (см. [`flyingGamePieces.ts`](src/data/flyingGamePieces.ts)).

**Важное архитектурное отличие от прежней сцены**: секция **не**
использует `position: sticky`. Пересечение с соседними блоками возможно
только если слой предметов скроллится вместе со страницей как обычный
контент — `sticky` держал бы вьюпорт «приклеенным», и всё, что улетает за
границы этого зафиксированного окна, было бы попросту не видно, а не
«пересекало» бы соседний блок. Вместо этого — обычный (non-pinned)
`ScrollTrigger` со `scrub`, `start: "top bottom"`, `end: "bottom top"`, на
секции без `overflow: hidden`.

Реальное движение (delay+duration каждого объекта) специально уложено в
первую треть общего таймлайна — в конце добавлен «холостой» отрезок
(`tl.to({}, { duration: 2.2 })`), который просто растягивает диапазон
скролла, ничего не анимируя. Без него объекты почти не успевали
разлететься к тому моменту, когда секция (и её якорь) уже уходит за
пределы экрана — «попасть» в Hero или Keywords было физически нечем.

Слой помечен `pointer-events-none`, а сама секция — `z-10`, чтобы
предметы визуально лежали поверх фона Hero/Keywords (в обычном порядке
отрисовки соседний блок в DOM перекрыл бы более ранний), но ниже фикс-шапки
(`z-50`) и не мешали кликам.

- `prefers-reduced-motion: reduce` — `ScrollTrigger` не создаётся вовсе:
  `gsap.set` сразу отрисовывает все 9 предметов в их конечном,
  разлетевшемся расположении, но без единого поворота и скраба —
  статичная, но живая композиция.
- Секция помечена `aria-hidden="true"` — чисто атмосферная, не несёт
  уникальной информации, не озвученной текстом Hero.

## Логотип

## Изображения и плейсхолдеры

Hero-фото и декор для scroll-сцены — реальные (сгенерированные)
изображения, уже на месте. Фотографий лофта и отзывов заказчик не
предоставил — они отрисовываются как временные градиентные заглушки с
подписью, что там должно быть (компонент `PlaceholderImage`). Полный
список путей, техзадание на каждую фотографию и таблица «исходник →
рабочий путь» — в [ASSETS.md](ASSETS.md). Чтобы подставить реальное
фото, достаточно положить файл с указанным именем в `public/assets/…` —
код менять не нужно.

## Производительность

- Все анимации (Framer Motion и GSAP) двигают только `transform`,
  `opacity` и `filter` — ни одна не трогает `width`/`height`/`top`/`left`,
  поэтому нет постоянных layout recalculation, только composite/paint.
- Hero-фото (1672×941) и оба фото для scroll-сцены (1448×1086 и
  1310×1200) конвертированы в WebP и не превышают отображаемый размер
  «с запасом под retina» — никаких исходников 5000–8000px.
- `<link rel="preload">` в [`index.html`](index.html) — только для
  hero-фото (`fetchpriority="high"`, кандидат в LCP) и двух исходников
  scroll-сцены; всё остальное ниже сгиба грузится через
  `loading="lazy"` (по умолчанию в `PlaceholderImage`).
- `aspect-ratio` зарезервирован под все изображения и плейсхолдеры —
  без сдвига layout при загрузке.

## Формы

Обе формы (блок «Праздник под ключ» и финальный блок бронирования)
работают полностью на клиенте: валидация обязательных полей (имя,
телефон, согласие на обработку данных), после успешной проверки —
демонстрационное сообщение об успехе. Реальная отправка не выполняется;
место для интеграции с CRM/бэкендом помечено комментарием `// TODO` в
`src/components/sections/TurnkeyParty.tsx` и `FinalCta.tsx`.

## Адаптивность

Макет проверен на 1440, 1024, 768 и 390px:

- Header превращается в компактный (лого + телефон + бургер) ниже `lg`
- Hero: фото на всю ширину в скруглённом контейнере (16:9 — все шесть
  человек видны целиком, лица не обрезаются ни на одном брейкпоинте),
  крупный serif-заголовок наложен на фото поверх тёмного градиента,
  отдельный текстовый блок и характеристики — ниже, а не сбоку
- Scroll-сцена: у мобильной версии свой набор координат и своя высота
  секции (см. выше), а не десктопная композиция, уменьшенная CSS-ом
- «Как проходит игра» и «Тайминг»: горизонтальный timeline на десктопе →
  вертикальный timeline на мобильном (одна и та же разметка, меняется
  направление flex)
- Галерея лофта: сетка на десктопе → горизонтальный swipe-скролл со
  scroll-snap и индикатором активного слайда на мобильном
- Все интерактивные элементы ≥44px в высоту, кнопки на мобильном — на
  всю ширину
- Горизонтальный скролл страницы отсутствует ни на одном брейкпоинте

## Доступность и SEO

- Один `<h1>` (заголовок Hero), логичная иерархия `h2`/`h3` по секциям
- `alt`-тексты у всех содержательных изображений, декоративная
  scroll-сцена помечена `aria-hidden`, `role="alert"` у ошибок форм,
  `aria-expanded`/`aria-controls` у FAQ и мобильного меню
- Видимый `:focus-visible` во всём проекте, skip-link «Перейти к
  основному содержимому»
- `lang="ru"`, `title`, `meta description`, Open Graph/Twitter Card,
  favicon, `loading="lazy"` для изображений вне первого экрана,
  зарезервированные пропорции (`aspect-ratio`) — без сдвига layout
- `prefers-reduced-motion` уважают и Framer Motion, и GSAP-сцена
